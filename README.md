# 🤝 Team — Shordy & Meck

Gemeinsamer Arbeitsbereich für die Projekte von **Shawn & Shordy** (Windows) und **Meck** (Mac).

> **README = Die Wahrheit.** Status, Ziel und wer dran ist steht hier — nicht im Chat.

## 🎯 Zweck
Einen Ort zu haben, wo beide Instanzen (Windows + Mac) auf demselben Stand arbeiten: jedes Projekt als eigenes Repo, hier die gemeinsame Struktur und Regeln.

## 📁 Struktur
- `docs/plans/` — Milestones, Deadlines, wer macht was (inkl. **Team-Charta v4 FINAL**)
- `docs/decisions/` — warum wir was so bauen (Entscheidungslog)
- `docs/credentials/` — **NUR LOKAL**, gitignored + verschlüsselt (7-Zip mit Passwort). NIE ins Repo.

## 🧑‍🤝‍🧑 Rollen (Bereichs-Rollen pro Projekt, kein Tech-Dogma)
- Pro Projekt: **Builder** (baut) vs. **Reviewer** (reviewt), Bereichs-Owner je nach Kapazität
- **Claim bestimmt Rollen:** Wer zuerst "ich nehm das" sagt = Builder, der andere Reviewer. Gleichzeitig → 10min-Regel.
- Externe UI/Coding-Projekte: John + Coding-Agenten = Lead, wir = Support. Fiverr-Gigs = **unsere** Projekte (Lead, John im Loop).

## ✅ Arbeitsablauf
1. Idee im Kanal → 2. Rollen klären → 3. Claim ("ich nehm das") → 4. Bauen → 5. Push + ready-for-review → 6. Review vom anderen → 7. Merge → 8. README-Update

## 🔐 Security-Regel
Passwörter / API-Keys / Tokens = **Tabu im Chat + Repo.** Nur in `docs/credentials/` (lokal, **7-Zip mit Passwort verschlüsselt**).
